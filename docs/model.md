# Model Explanation

## What the model is doing

The project uses supervised learning to classify whether a patient is likely to be healthy or to show knee osteoarthritis risk markers based on clinical inputs. In supervised learning, the model learns from known examples where the target label is already available (`group`).

## Inputs and target

### Features (X)

- `age`
- `gender`
- `BMI`
- `VAS score`
- `JPR_30`
- `JPR_45`
- `JPR_60`

### Target (y)

- `0`: healthy
- `1`: knee osteoarthritis

## Algorithms compared

The project evaluated the following models using stratified 5-fold cross-validation:

- Logistic Regression
- KNN
- Decision Tree
- Random Forest
- SVM

## Why cross-validation matters

Stratified 5-fold cross-validation is used so the model is evaluated on multiple balanced data splits, which helps reduce overfitting and gives a more stable estimate of real-world performance on limited datasets.

## Why F1, precision, and recall matter

For a small prototype health dataset, accuracy alone can be misleading. Precision, recall, and F1 help describe the balance between correctly identifying positive OA risk cases and avoiding false positives.

- Precision: how many predicted OA cases are genuinely OA risk cases
- Recall: how many actual OA cases are correctly identified
- F1: the harmonic balance between precision and recall

## Why Random Forest was selected

Random Forest was selected because it produced the strongest F1 performance in the current training experiment. This is the model currently saved as `models/oa_model.pkl`.

## Current metrics

Current prototype evaluation results from the project training workflow:

| Model | Accuracy | Precision | Recall | F1 |
|---|---:|---:|---:|---:|

| Logistic Regression | 0.671 | 0.679 | 0.647 | 0.653 |

## Feature importance

Random Forest provides variable importance estimates that help interpret which clinical markers contribute more strongly to the model’s decision-making. These values are included in the evaluation outputs generated by `ml/evaluate_model.py`.

## Limitations

- Small dataset size
- Prototype research setting
- Not a validated clinical diagnostic system
- Screening output is intended for decision support, not diagnosis

## Data leakage precautions

The model intentionally excludes `K-L grade` and `KOA period` from the input features to avoid leaking disease-related information into the predictor set. The code also excludes patient IDs from model inputs.

## Screening vs diagnosis

This project supports AI-assisted risk screening and prototype assessment. It is not intended to replace clinical evaluation or medical diagnosis. Final clinical interpretation must always rest with a qualified healthcare professional.
